# Vive 仕様書 (日本語)

## 概要
Viveは、複数のGit Worktree、Tmuxセッション、およびAIエージェント（Claude Code）を一元管理するための「AI開発オーケストレーター」です。
ユーザーはViveを通じて、複数の並行開発タスクを俯瞰し、監視し、必要に応じて介入・指示を行うことができます。

## ユーザー体験 (UX) のゴール

Viveは単なるランチャーではなく、**「AIエージェントの司令室 (Cockpit)」** として機能します。

1.  **Overview**: 全プロジェクト・全タスクの進行状況を一目で把握できる。
2.  **Monitor**: 特定のタスクの画面（Claudeの出力）をリアルタイムで覗き見ることができる。
3.  **Command**: わざわざセッションに入り込まなくても、外から指示（承認や追加プロンプト）を飛ばせる。
4.  **Dive**: 必要であれば瞬時にその開発環境（Tmuxセッション）に没入し、コードを編集できる。

## 画面構成 (TUI Layout)

画面は大きく3つのエリアに分割されます。

```text
+---------------------+---------------------------------------------------------------+
| [1] Sidebar         | [2] Preview Area (Tmux Pane Capture)                          |
| (Projects & Tasks)  |                                                               |
|                     |  Claude Code >                                                |
| > mechanix          |  I have analyzed the error. The issue is in main.rs.          |
|   + feature/ui      |  Shall I fix it? [y/n]                                        |
|   + fix/bug-123     |                                                               |
|     (🟡 Wait)       |                                                               |
|                     |                                                               |
|   vive              |                                                               |
|   + main            |                                                               |
|     (🟢 Work)       |                                                               |
|                     |                                                               |
+---------------------+---------------------------------------------------------------+
| [3] Command Input Area                                                              |
| > y                                                                                 |
+-----------------------------------------------------------------------------------+
```

### [1] Sidebar (Navigation)
- **構造**: プロジェクト（リポジトリ）とタスク（Worktree）のツリー構造。
- **ステータス表示**:
    - 🟢 **Work**: エージェントが思考中・実行中。
    - 🟡 **Wait**: エージェントがユーザーの入力（承認など）を待っている。
    - ⚪ **Idle**: セッションは存在するが、エージェントは稼働していない。
    - 🔴 **Error**: プロセスが異常終了した。
- **操作**: `j/k` または矢印キーで選択。選択されたタスクがプレビュー対象となる。

### [2] Preview Area
- **機能**: 選択中のタスクに対応するTmuxペインの内容を表示する。
- **更新**: 定期的（例: 0.5秒ごと）に `tmux capture-pane` を実行し、最新の状態を反映する。
- **スクロール**: プレビューエリア内でのスクロールが可能。

### [3] Command Input Area
- **機能**: 選択中のタスク（のClaudeプロセス）に対して、標準入力を送信する。
- **動作**: ここに入力してEnterを押すと、バックグラウンドで `tmux send-keys` が実行される。
- **ユースケース**:
    - Claudeの「実行しますか？ [y/n]」に対して `y` を送る。
    - 追加の指示（プロンプト）を送る。
    - `Ctrl+C` などのシグナルを送る（コマンド対応が必要）。

## キー操作一覧

| キー | 動作 |
| :--- | :--- |
| `j` / `↓` | 次のタスクへ移動 |
| `k` / `↑` | 前のタスクへ移動 |
| `Enter` / `o` | **Dive**: 選択中のタスクのTmuxセッションに切り替える（Attach） |
| `i` | **Input**: コマンド入力エリアにフォーカスする |
| `Esc` | 入力モードから抜ける / 選択解除 |
| `q` | Viveを終了する |

## 技術的仕様（並行開発用）

各機能の実装担当者は以下に従ってください。

### 1. Core / Discovery (#20)
- **データ構造**:
    - `Project`: 名前、パス、Worktreeのリストを持つ。
    - `Worktree`: ブランチ名、パス、**対応するTmuxセッション/ウィンドウID** を特定できる情報を持つ。
- **ID管理**: プロジェクト名とブランチ名から一意なID（例: `mechanix:fix-bug-123`）を生成し、これをTmuxセッション名として使用する。

### 2. Tmux Orchestrator (#21)
- **Capture**: `capture_pane(session_id: &str, lines: usize) -> Result<String>` を実装する。
- **Send**: `send_keys(session_id: &str, input: &str) -> Result<()>` を実装する。
- **Attach**: 現在の端末プロセスを `tmux attach -t <session_id>` に置き換える処理を実装する。

### 3. Process Monitor (#22)
- **入力待ち判定**:
    - プロセスステータスだけでなく、Tmuxペインの**最後の数行**を解析する。
    - パターンマッチ: `(y/n)`, `Wait`, `> ` などが末尾にある場合を「Wait」と判定するロジックが必要。

### 4. TUI / Main (#19)
- **Input Mode**: `ratatui-textarea` 等を使用して、入力フィールドを実装する。
- **非同期更新**: ユーザーが入力中でも、バックグラウンドでプレビューエリアが更新されるように、非同期ランタイム（Tokio）とチャネルを利用したアーキテクチャにする。
